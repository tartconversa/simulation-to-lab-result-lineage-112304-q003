# 仿真—实测验证谱系应用说明

本应用把**仿真批次**与**实验室实测结果**作为两类不同观测接入，建立可追溯的
验证关系，判断每条模拟预测在具体条件下属于：

- `validated`（验证）：同指标、同单位、完整实验，差异落在扩展不确定度容差内；
- `contradicted`（否定）：上述条件可比，但差异超出容差；
- `not_comparable`（尚不可比较）：缺测、单位不一致、实验未完成或无共同指标，
  并附结构化原因码。

仿真输出与实测记录**不会被当作同一种观测混算**。全部数据均为本地合成数据，
不包含真实实验室、研究人员或实验结果；仅依赖 Python 3.11–3.14 标准库。

## 1. 数据模型与不可变性

SQLite 库由以下表组成（见 `src/simulation_to_lab_result_lineage/schema.py`）：

| 表 | 性质 | 说明 |
| --- | --- | --- |
| `simulation_runs` | 仅追加原始表 | 模型版本、输入哈希、随机种子、运行环境、结果引用 |
| `lab_runs` | 仅追加原始表 | 样品、方案版本、设备、批次状态（complete/failed/aborted） |
| `measurements` | 仅追加原始表 | 指标、值、单位、测量误差、重复号、**来源批次 `batch_id`** |
| `validation_links` | 仅追加原始表 | 仿真—实验配对、条件映射版本、链接审核状态 |
| `ingest_batches` / `ingest_issues` | 台账 | 按内容哈希去重的接入批次；问题行隔离留痕 |
| `lab_run_corrections` | 仅追加台账 | 样品关联等更正；**原始 `lab_runs` 行永不修改** |
| `comparison_facts` | 版本化事实 | 同一 `fact_uid` 多版本追加；状态 active / re_review_pending / superseded |
| `fact_revisions` | 修订台账 | created / re_review_pending / recomputed 全过程留痕 |
| `signoffs` | 签收记录 | 模型负责人、实验负责人对**具体事实版本**分别签收 |

不可变保证：

1. 原始表只有 INSERT；重复主键、非法取值被隔离进 `ingest_issues`，不覆盖首值；
2. 比较结论变化时追加新版本，旧版本置 `superseded` 并保留全部原始取值；
3. 报告可按 `as_of` 时间点重建，只采用该时点之前已存在的事实版本与签收。

## 2. 判定规则（`domain.py`）

对一条链接上每个候选指标（取两侧指标并集），按顺序判定：

1. 仿真侧无该指标 → `not_comparable / missing_simulation_measurement`；
2. 实测侧无该指标 → `not_comparable / missing_lab_measurement`；
3. 实验批次非 `complete`（failed/aborted）→ `not_comparable / lab_run_not_complete`，
   测量记录保留但不能自动充当验证证据；
4. 两侧单位不一致 → `not_comparable / unit_mismatch`，应用**不做隐式单位换算**；
5. 两侧均无任何测量 → `not_comparable / no_shared_metric`，失败/空记录仍留痕；
6. 可比时计算重复测量均值，容差
   `T = z · sqrt(mean(u_sim)² + mean(u_lab)²)`（默认 z=2）：
   - `|mean_sim − mean_lab| ≤ T` → `validated`；否则 `contradicted`。
   - 双侧不确定度均为 0 时容差为 0，任何非零差异即否定，避免零容差被误判为必验证。

## 3. 角色与职责边界

| 角色 | 应用内动作 | 边界 |
| --- | --- | --- |
| 模型负责人 `model_owner` | 对事实版本签收 `confirmed/rejected`，确认预测版本与适用条件 | 不代替实验侧判断样品/设备证据 |
| 实验负责人 `experiment_owner` | 对事实版本签收，判断实测证据与样品条件是否有效 | 不代替模型侧确认预测适用性 |
| 数据平台 | 接入校验、问题隔离、事实版本化、修订台账、历史重建 | 不自动改写任何结论；双签收缺一即不计入"双确认" |

签收绑定 `(fact_uid, version_no, role)`；事实升级到新版本后，旧签收不自动沿用。

## 4. 增量资料与待复核流程

```
新测量/更正到达
   │  接入（内容哈希去重；问题行隔离）
   ▼
按测量行 batch_id 反查受影响链接（含老引用上的新增重复）
   │
   ▼
活动事实 → re_review_pending（旧值原样保留，写修订台账）
   │
   ▼
按当前资料重算 → 追加新版本 active，旧版本 superseded
```

- `refresh`：增量接入测量并自动完成"待复核 → 重算"；`--no-recompute` 可只置待复核；
- `correct-sample`：样品关联更正写入 `lab_run_corrections`，关联事实进入待复核；
- 原始比较所用版本始终可经 `versions` 与 `report --as-of` 重建。

## 5. 命令行操作手册

```sh
# 生成受控合成夹具（第一批 + 第二批增量测量）
python -m simulation_to_lab_result_lineage make-fixture --out ./demo/v1
python -m simulation_to_lab_result_lineage make-fixture --out ./demo/v2 --update

# 接入资料目录（重复内容自动 skipped_unchanged）
python -m simulation_to_lab_result_lineage ingest --data-dir ./demo/v1 --db work.sqlite

# 建立比较事实（幂等；--now 注入确定性时间戳）
python -m simulation_to_lab_result_lineage build-facts --db work.sqlite --now 2026-10-20T00:00:00Z

# 查询：按结论/状态/链接过滤；--all-versions 含历史版本
python -m simulation_to_lab_result_lineage query --db work.sqlite --verdict validated
python -m simulation_to_lab_result_lineage versions --db work.sqlite --link L-3008 --metric yield

# 增量接入、待复核与重算
python -m simulation_to_lab_result_lineage refresh --db work.sqlite \
    --data-dir ./demo/v2 --measurements-only --now 2026-10-24T00:00:00Z

# 双负责人签收（绑定事实版本）
python -m simulation_to_lab_result_lineage signoff --db work.sqlite \
    --link L-3001 --metric binding --version 1 \
    --role model_owner --owner M-OWNER --decision confirmed --comment "模型v3适用"
python -m simulation_to_lab_result_lineage signoff --db work.sqlite \
    --link L-3001 --metric binding --version 1 \
    --role experiment_owner --owner E-OWNER --decision confirmed --comment "证据有效"

# 样品关联更正（原始行不变）与手动重算
python -m simulation_to_lab_result_lineage correct-sample --db work.sqlite \
    --experiment EXP-3002 --sample SAMPLE-B2 --reason "标签贴反" --by STEWARD-1
python -m simulation_to_lab_result_lineage recompute-pending --db work.sqlite

# 报告：当前视图 / 历史时点重建；台账查询
python -m simulation_to_lab_result_lineage report --db work.sqlite
python -m simulation_to_lab_result_lineage report --db work.sqlite --as-of 2026-10-21T00:00:00Z
python -m simulation_to_lab_result_lineage issues --db work.sqlite
python -m simulation_to_lab_result_lineage batches --db work.sqlite
python -m simulation_to_lab_result_lineage corrections --db work.sqlite
```

所有命令支持 `--json` 输出机器可读结果。以 src 布局运行时设置
`PYTHONPATH=src`（或 `pip install -e .`）。

## 6. 受控合成夹具场景（`synthetic.py`）

| 链接 | 场景 | 预期结论 / 原因码 |
| --- | --- | --- |
| L-3001 | 同单位、差异在容差内 | `validated` |
| L-3002 | 双侧重复测量、差异超容差 | `contradicted` |
| L-3003 | 同指标 kJ vs J | `not_comparable / unit_mismatch` |
| L-3004 | failed 实验，测量保留 | `not_comparable / lab_run_not_complete` |
| L-3005 | 实测侧缺该指标 | `not_comparable / missing_lab_measurement` |
| L-3006 | 仿真侧缺该指标 | `not_comparable / missing_simulation_measurement` |
| L-3007 | aborted 且两侧均无测量 | `not_comparable / no_shared_metric` |
| L-3008 | 第二批补重复与新指标，触发版本升级 | 初始/重算均 `validated`，新增 stability 事实 |

夹具同时包含接入问题样本：孤立测量引用（保留+台账）、重复测量主键（隔离首值）、
负不确定度（隔离）。基线 `data/` 的 60 条链接因两侧指标体系不重合，
全部判为 `not_comparable`，38 条悬空引用登记为 `orphan_result_ref`。
